= Chronicle Quality Rules
:toc:
:sectnums:
:lang: en-GB
:source-highlighter: rouge

This module packages shared quality configuration and documentation used across Chronicle projects.
It provides:

* Checkstyle rule sets and custom checks (including the Meaningful Message Check);
* SpotBugs include and exclude filters;
* PMD rulesets and suppression guidance;
* shared quality and diagnostics guidance that other modules can reference.

Documentation under `src/main/docs` is provided for development context and is not packaged in the release JAR.

The goal is to keep quality and compliance rules centralised so that individual repositories can reuse them with minimal boilerplate.

== Maven Usage

Most Chronicle modules inherit these rules through a parent POM (for example `chronicle-enterprise-root-pom`), but they can also consume the artefact directly in a build.

=== Checkstyle

To apply the Chronicle Checkstyle rules in a standalone Maven project, add the plugin and dependency:

[source,xml]
----
<plugins>
<plugin>
    <groupId>org.apache.maven.plugins</groupId>
    <artifactId>maven-checkstyle-plugin</artifactId>
    <version>3.3.1</version>
    <executions>
        <execution>
            <id>validate</id>
            <phase>validate</phase>
            <goals>
                <goal>check</goal>
            </goals>
        </execution>
    </executions>
    <configuration>
        <configLocation>net/openhft/quality/checkstyle26/chronicle-baseline-checkstyle.xml</configLocation>
        <failOnViolation>${quality.enforced}</failOnViolation>
        <logViolationsToConsole>true</logViolationsToConsole>
        <includeTestSourceDirectory>true</includeTestSourceDirectory>
        <violationSeverity>warning</violationSeverity>
    </configuration>
    <dependencies>
        <dependency>
            <groupId>com.puppycrawl.tools</groupId>
            <artifactId>checkstyle</artifactId>
            <version>9.3</version>
        </dependency>
        <dependency>
            <groupId>net.openhft</groupId>
            <artifactId>quality</artifactId>
            <version>2026.0</version>
        </dependency>
    </dependencies>
</plugin>
<plugin>
    <groupId>com.github.spotbugs</groupId>
    <artifactId>spotbugs-maven-plugin</artifactId>
     <version>${spotbugs.maven.plugin.version}</version>
    <configuration>
        <effort>Max</effort>
        <threshold>Low</threshold>
        <includeTests>true</includeTests>
        <failOnError>${quality.enforced}</failOnError>
        <includeFilterFile>net/openhft/quality/spotbugs26/chronicle-spotbugs-include.xml</includeFilterFile>
        <excludeFilterFile>net/openhft/quality/spotbugs26/chronicle-spotbugs-exclude.xml</excludeFilterFile>
    </configuration>
    <dependencies>
        <dependency>
            <groupId>net.openhft</groupId>
            <artifactId>quality</artifactId>
            <version>2026.0</version>
        </dependency>
    </dependencies>
    <executions>
        <execution>
            <id>spotbugs-main</id>
            <!-- Bind after test classes are compiled so includeTests=true analyses src/test/java as well. -->
            <phase>process-test-classes</phase>
            <goals>
                <goal>check</goal>
            </goals>
        </execution>
    </executions>
</plugin>
</plugins>
----

NOTE: In Chronicle parent POMs the quality checks are bound to the `quality` profile and only run when `-Pquality` is enabled. The profile sets `quality.enforced` to true by default, but it can be overridden in a consuming project's properties if warning-only output is preferred.

For builds that need both the legacy Java 8 toolchain and newer Java 21+ runtimes, Chronicle parent POMs select `${spotbugs.maven.plugin.version}` by JDK: `4.8.6.6` for Java `<= 20` and `4.9.8.1` for Java `21+`.

Parent POMs such as `root-parent-pom` and `chronicle-enterprise-root-pom` already wire this plugin; most Chronicle modules should prefer that route rather than duplicating configuration.

== Gradle Usage

To apply the Chronicle Checkstyle rules in a standalone Gradle build, add a Checkstyle task that fails the build on violations:

[source,groovy]
----
plugins {
    id 'checkstyle'
}

checkstyle {
    toolVersion = '9.3'
    config = resources.text.fromArchiveEntry(configurations.checkstyle, 'net/openhft/quality/checkstyle26/chronicle-baseline-checkstyle.xml')
}

dependencies {
    checkstyle 'com.puppycrawl.tools:checkstyle:9.3'
    checkstyle 'net.openhft:quality:2026.0'
}

def qualityEnforce = (project.findProperty('quality.enforced') ?: 'true').toString().toBoolean()
tasks.withType(Checkstyle).configureEach {
    ignoreFailures = !qualityEnforce
    maxWarnings = qualityEnforce ? 0 : Integer.MAX_VALUE
}
----

=== SpotBugs

SpotBugs configuration (rule filters, effort and threshold settings) is also provided from this module and surfaced by the parent POMs.
To consume it directly, add the `spotbugs-maven-plugin` with a dependency on `chronicle-quality-rules` in a similar fashion to the Checkstyle example above.

=== JaCoCo Code Coverage

This module enforces code coverage thresholds via JaCoCo:

* *Line coverage*: 95.4%
* *Branch coverage*: 84.2%

Coverage is checked during the `verify` phase automatically.

=== PIT Mutation Testing

This module includes an opt-in PIT (pitest) mutation testing profile.
Mutation testing measures test effectiveness by introducing faults into bytecode and checking whether tests detect them.

To run mutation testing:

[source,bash]
----
mvn -Ppitest verify
----

==== Configuration

The `pitest` profile is configured with:

[cols="1,2"]
|===
|Setting |Value

|pitest-maven
|1.22.0

|pitest-junit5-plugin
|1.2.1

|Mutation threshold
|88%

|Coverage threshold
|95%

|Full mutation matrix
|enabled
|===

==== Current Coverage

Run `mvn -Ppitest verify` to generate current coverage reports.
Reports are written to `target/pit-reports/index.html`.

Coverage levels must meet the configured thresholds (88% mutation, 95% line) for the build to pass.

==== JUnit 5 Compatibility

This project uses JUnit Jupiter 5.10.5 with JUnit Platform 1.10.5 (defined in `third-party-bom`).
The pitest-junit5-plugin 1.2.1 is compatible with these versions.

NOTE: If upgrading pitest-junit5-plugin, version 1.2.2+ addresses a transitive dependency conflict with `junit-platform-launcher`.
See https://github.com/pitest/pitest-junit5-plugin/releases[release notes] for details.
