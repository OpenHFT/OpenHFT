== Purpose
This module validates that all dependencies declared in the `third-party-bom` remain usable on Java 8 (baseline) and Java 21 (current LTS). It provides two layers of validation: class loading tests confirm artifact resolution and bytecode compatibility, whilst minimal usage tests verify basic runtime behaviour.

== Test Categories and Coverage

=== Class Loading Tests
`ClassLoadingSmokeTest` dynamically generates coverage to load representative classes from each third-party artefact. Tests are grouped by dependency category:

* Observability (OpenTelemetry, Prometheus)
* Serialisation (JSONAssert, SnakeYAML, XStream, Jackson, Jettison, BSON)
* MongoDB drivers (legacy, GridFS, core, sync)
* Networking (Undertow, Jetty, Netty, Grizzly, MINA, XNIO, MockWebServer)
* Logging (Log4j 2, Log4j 1.x, SLF4J, Logback, Commons Logging)
* Collections (Koloboke, Trove4j)
* Databases (HSQLDB)
* Testing frameworks (JUnit, JMH, Hamcrest, Mockito, PowerMock, EasyMock, Guava Testlib)
* OSGi (OSGi core/compendium, Pax Exam, Felix framework, Pax URL)
* Tooling and utilities (JCommander, Gson, Unirest, Joda-Time, Commons Email, JGit, Maven Model, JavaPoet, ProGuard)

=== Behavioural Smoke Tests
Behavioural smoke tests validate runtime behaviour beyond class loading, organised by category:

* Core categories retained: `MinimalObservabilitySmokeTest`, `MinimalSerializationSmokeTest`, `MinimalNetworkingSmokeTest`, `MinimalLoggingSmokeTest`, `MinimalUtilitiesSmokeTest`, `MinimalDatabaseSmokeTest`.
* Additional focused smokes:
** Web clients and websocket stacks: `OkHttpSmokeTest`, `JettyWebSocketSmokeTest`.
** Build and tooling: `GitBuildAndAnnotationsSmokeTest`, `JavaPoetSmokeTest`, `ProGuardParserSmokeTest`, `ClassGraphSmokeTest`.
** CLI/HTTP/time/email/JSON: `CliJsonHttpTimeEmailSmokeTest`, `CommonsLibrariesSmokeTest`, `JettisonSmokeTest`.
** Metrics and native FFI: `MetricsAndFfiSmokeTest`, `NativeAndCollectionsSmokeTest`.
** Networking stacks: `NioAndNetworkStacksSmokeTest` (Grizzly, MINA, Netty, ProGuard presence).
** Test frameworks and mocking: `JupiterSmokeTest`, `JupiterParamsSmokeTest`, `JUnitPlatformLauncherSmokeTest`, `JUnit4VintageHamcrestSmokeTest`, `JUnitMigrationSupportSmokeTest`, `MockitoSmokeTest`, `EasyMockSmokeTest`, `PowerMockPresenceSmokeTest`, `JmhSmokeTest`.
** Domain-specific libraries: `QuickFixSmokeTest`, `AnnotationsAndGuavaTestlibSmokeTest`, `JavaxInjectSmokeTest`, `OsgiAndPaxSmokeTest`.

Each test is intentionally offline-friendly (ports bound to `0`, no external services) and Java 8 compatible.

== Build and Test

=== Run all smoke tests
[source,bash]
----
mvn -pl third-party-smoke test
----

=== Run specific test category
[source,bash]
----
mvn -pl third-party-smoke -Dtest=ClassLoadingSmokeTest test
mvn -pl third-party-smoke -Dtest=MinimalObservabilitySmokeTest test
mvn -pl third-party-smoke -Dtest=MinimalSerializationSmokeTest test
----

=== Run all minimal usage tests
[source,bash]
----
mvn -pl third-party-smoke -Dtest="Minimal*SmokeTest" test
----

=== Expected scope
* `ClassLoadingSmokeTest`: dynamic coverage of all BOM-managed artefacts.
* Behavioural tests: targeted smokes per dependency family (networking, observability, logging, tooling, mocking, CLI/HTTP/time/email, FFI).
* Vintage coverage: JUnit 4 and PowerMock presence validated alongside Jupiter.

== Current Focus
The module enforces Java 8 bytecode compatibility via Maven Enforcer Plugin's `enforceBytecodeVersion` rule. Any dependency compiled for Java 9+ (classfile version > 52) will fail the build unless explicitly excluded. Current exclusions:

* `org.hsqldb:hsqldb` – Java 11 bytecode (jdk8 classifier available)
* `org.mongodb:bson-record-codec` – Java 17 bytecode (uses records)

See link:version-issues.adoc[version-issues.adoc] for details and follow-up actions.

== Open Topics
* *SLF4J binding warnings*: multiple SLF4J implementations on the test classpath trigger "multiple bindings found" warnings. Tolerated for now to validate each binding loads correctly.
* *HSQLDB dual artefacts*: both base artefact and `jdk8` classifier remain. Confirm if both are required or consolidate to the classifier.
* *Mongo record codec*: confirm whether `bson-record-codec` is still pulled with the 4.11.1 driver set.
* *Baseline watchpoints*: track OTel 1.33+, OkHttp/okio/Kotlin baseline shifts, and Jetty 9.4.x security drops.

== Future Work

* Integrate with `third-party-bom` version bump workflow to automatically revalidate on dependency updates
* Reduce SLF4J binding conflicts by using separate test execution groups
* Audit OSGi and Pax Exam dependencies to confirm downstream consumers still require them
