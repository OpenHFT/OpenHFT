== Purpose

This module validates that all dependencies declared in the `third-party-bom` remain usable on Java 8 (baseline) and Java 21 (current LTS).
It provides two layers of validation: class loading tests confirm artifact resolution and bytecode compatibility, whilst minimal usage tests verify basic runtime behaviour.

== Test Categories

=== Class Loading Tests

`ClassLoadingSmokeTest` dynamically generates 85+ tests to load representative classes from each third-party artefact.
Tests are grouped by dependency category:

* Observability (OpenTelemetry, Prometheus)
* Serialisation (JSONAssert, SnakeYAML, Jackson, Jettison, BSON)
* MongoDB drivers (legacy, GridFS, core, sync)
* Networking (Undertow, Jetty, Netty, Grizzly, MINA, XNIO, MockWebServer)
* Logging (Log4j 2, SLF4J, Commons Logging)
* Collections (Koloboke, Trove4j)
* Databases (HSQLDB)
* Testing frameworks (JUnit, JMH, Hamcrest, Mockito, PowerMock, EasyMock, Guava Testlib)
* OSGi (OSGi core/compendium, Pax Exam, Felix framework)
* Additional peer dependencies (JCommander, Gson, Unirest, Joda-Time, Commons Email, Maven Model)

=== Minimal Usage Tests

Minimal usage tests validate basic runtime behaviour beyond class loading, organised by category:

* `MinimalObservabilitySmokeTest` – Prometheus counter registration and OpenTelemetry tracer initialisation
* `MinimalSerializationSmokeTest` – JSON, YAML, XML serialisation round-trips
* `MinimalNetworkingSmokeTest` – web server framework initialisation (Undertow, Jetty, Netty, Grizzly, MockWebServer)
* `MinimalLoggingSmokeTest` – Log4j2 and SLF4J logger creation
* `MinimalUtilitiesSmokeTest` – collections (Trove4j), utilities (Commons Lang/CLI), code generation (JavaPoet), compression (Snappy), classpath scanning (ClassGraph), native access (JNA, JNR), time (Joda-Time), email (Commons Email)
* `MinimalDatabaseSmokeTest` – MongoDB connection string parsing, HSQLDB driver access

=== Legacy JUnit4 Test

`LegacyJUnit4SmokeTest` verifies the JUnit 4 vintage engine correctly executes legacy `@Test` annotations.

== Build and Test

=== Run all smoke tests

[source,bash]
----
mkdir -p logs
mvn -pl third-party-smoke verify -l logs/mvn-third-party-smoke.log
----

Review `logs/mvn-third-party-smoke.log` and treat any warnings or errors as defects (the goal is a clean build, not just a zero exit code).

To validate the alternative SLF4J binding (NOP):

[source,bash]
----
mvn -pl third-party-smoke -Pslf4j-nop verify -l logs/mvn-third-party-smoke-slf4j-nop.log
----

=== Run specific test category

[source,bash]
----
mvn -pl third-party-smoke -Dtest=ClassLoadingSmokeTest test -l logs/mvn-third-party-smoke-ClassLoadingSmokeTest.log
mvn -pl third-party-smoke -Dtest=MinimalObservabilitySmokeTest test -l logs/mvn-third-party-smoke-MinimalObservabilitySmokeTest.log
mvn -pl third-party-smoke -Dtest=MinimalSerializationSmokeTest test -l logs/mvn-third-party-smoke-MinimalSerializationSmokeTest.log
----

=== Run all minimal usage tests

[source,bash]
----
mvn -pl third-party-smoke -Dtest="Minimal*SmokeTest" test -l logs/mvn-third-party-smoke-MinimalSmokeTests.log
----

== Current Focus

The module enforces Java 8 bytecode compatibility via Maven Enforcer Plugin's `enforceBytecodeVersion` rule.
Any dependency compiled for Java 9+ (classfile version > 52) will fail the build unless explicitly excluded.
Current exclusions:

* `org.hsqldb:hsqldb` – Java 11 bytecode (jdk8 classifier available)
* `org.mongodb:bson-record-codec` – Java 17 bytecode (uses records)

See link:version-issues.adoc[version-issues.adoc] for details and follow-up actions.

== Open Topics

* *Clean builds*: keep the build output free of warnings (capture logs with `-l` and review them, do not rely on exit codes alone).
* *SLF4J bindings*: validate bindings separately via `-Pslf4j-simple` (default) and `-Pslf4j-nop` to avoid multiple-provider warnings.
* *HSQLDB classifier requirement*: confirm the `jdk8` classifier remains necessary as upstream evolves.

== Future Work

* CI matrix: currently runs on Java 8 and 21; consider adding 11 and 17 to catch runtime-specific regressions
* Integrate with `third-party-bom` version bump workflow to automatically revalidate on dependency updates
* Audit OSGi and Pax Exam dependencies to confirm downstream consumers still require them
